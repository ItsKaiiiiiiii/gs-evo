# 数据边界：什么会离开这台机器，什么永远不会

> gs-evo 是自托管系统：数据的边界画在你团队自己的基础设施里（云端部署在团队自己的服务器上，不经过任何第三方）。
> 本页面向**被接入机器的使用者**——你有权知道、也有权控制。

## 会离开这台机器的（仅限白名单目录）

| 数据 | 何时 | 去向 |
|------|------|------|
| 白名单目录下的 skill 文件（如 `~/.claude/skills/**`） | 仅当你（或管理员）点击「扫描 / 获取」，或发布流程需要 | 云端对象存储（内容寻址，团队服务器） |
| skill 清单（名称/版本/哈希） | worker 每次连接与周期同步 | 云端数据库 |
| 设备基础信息（主机名/平台/worker 版本/白名单目录列表） | 连接时 | 云端数据库 |
| 任务的过程输出与结果 | 仅当管理员向本机下发任务 | 云端数据库 |

## 永远不会离开这台机器的

- 白名单目录之外的**一切文件**
- 环境变量、API 密钥、SSH 密钥、浏览器数据
- 白名单目录之外任何进程的内存与磁盘

## 你的三项权利（本机即可行使，无需管理员）

| 命令 | 作用 |
|------|------|
| `gs-worker history` | 查看云端对本机做过的**每一件事**（本地审计日志，只追加） |
| `gs-worker pause` | 暂停：云端指令不再执行（心跳保持，控制台显示"已暂停"） |
| `gs-worker logout` | 彻底退出：删除本机凭证，云端设备转为离线 |

## 管理侧约束（对管理员）

- 每条指令落库审计：谁、何时、对哪台机器、做了什么、结果如何
- 下发的安装包必须经过云端 ed25519 签名，本机验签后才执行
- skill 安装只写白名单目录（worker 二次校验，不在白名单直接拒绝）
- viewer 角色只读；操作者身份全量可见
